# AutoForge — 자율형 개발 자동화

한국어로 작업을 입력하면 **요구사항 분석 → 설계 → 코딩 → 실제 테스트 → 오류 수정 → 배포 확인**을 이어서 수행하는 로컬 시스템입니다. 기본 저장소는 [flexda/dev-auto-test](https://github.com/flexda/dev-auto-test)입니다. 구현 전 초기 저장소(README만 있던 상태)를 실제로 복제해 연결을 검증했습니다.

## 바로 실행

Node.js 24와 npm을 준비한 뒤 아래 명령으로 실행하세요.

```sh
git clone https://github.com/flexda/dev-auto-test.git
cd dev-auto-test
npm ci
npm run dev
```

[관리 화면 열기](http://127.0.0.1:4317)에서 **기능 데모**를 선택하면 인증정보 없이 전체 흐름을 확인할 수 있습니다. 내장 예제는 사전에 작성한 가격 계산기 코드의 세금 오류를 실제로 검출하고, 수정한 코드를 다시 테스트한 뒤 로컬 페이지로 제공합니다. 데모는 AI를 호출하지 않습니다.

프로젝트의 npm 명령은 함께 설치되는 Node 24 실행기를 사용합니다.

## 실제 AI 개발 실행

1. `.env.example`을 `.env`로 복사하고 `AI_GATEWAY_API_KEY`를 설정합니다. 키를 채팅이나 저장소에 붙여 넣지 마세요.
2. Docker Desktop을 시작합니다. 기본 이미지 `node:24-alpine`은 첫 실행 시 내려받습니다. 미리 준비하려면 `docker pull node:24-alpine`을 실행하세요.
3. 서버를 시작하거나 재시작합니다.
4. 관리 화면에서 **AI 개발**을 선택하고 GitHub 주소와 구체적인 요구사항을 입력합니다.

예: “할 일 관리 웹 앱을 만들어줘. 할 일 추가·완료·삭제와 우선순위 선택을 지원하고, 각 기능에 대한 테스트를 작성해줘. build 실행 시 dist/index.html과 정적 자산이 생성되도록 해줘.”

현재 AI와 Docker 연결정보가 없는 상태에서는 AI 작업을 `연결 필요`로 기록합니다. 내장 예제와 실제 AI 실행은 화면에 구분해서 표시합니다. AI 모델은 환경변수 `AUTOFORGE_MODEL`로 선택합니다. 기본값은 Eve 초기화 도구의 `openai/gpt-6-luna-fast`이며 공식 AI Gateway 모델 목록에서 지원 여부를 확인했습니다.

공개 GitHub 저장소는 토큰 없이 복제합니다. 비공개 저장소에는 읽기 권한이 있는 `GITHUB_TOKEN`이 필요합니다. 원격 저장소에 커밋하거나 푸시하지 않으며, 생성 코드·기존 파일 변경 패치·새 파일 원문을 실행 결과에 저장합니다.

## 배포

- **로컬 미리보기**: 검증한 `dist`, `out`, `build`, `public` 폴더의 정적 파일을 제공합니다. 실제 HTTP 응답의 HTML이 산출물과 일치해야 완료됩니다.
- **Vercel Preview**: `.env`에 `VERCEL_TOKEN`, `VERCEL_PROJECT_ID`와 필요 시 `VERCEL_TEAM_ID`를 설정하고 배포 대상을 선택합니다. 전용 정적 사이트 프로젝트를 권장합니다. 배포 ID를 저장하고 상태·URL 응답을 확인합니다.

현재 버전은 **npm 기반 Node.js 프로젝트와 정적 웹 결과물**을 지원합니다. 서버 애플리케이션·데이터베이스 구축·프로덕션 승격은 포함하지 않습니다. 외부 배포 인증정보가 없으므로 Vercel의 실제 배포는 아직 검증하지 않았습니다. Docker 데몬도 현재 꺼져 있어 기존 저장소의 컨테이너 검사는 아직 실행하지 않았습니다.

## 각 구성요소가 하는 일

- **관리 화면**: 작업을 입력하고 단계, 생성 파일, 테스트 결과, 배포 주소를 확인합니다.
- **개발 엔진**: AI가 요구사항과 설계를 만들고 파일을 작성하며, 실패 내용을 보고 정해진 횟수 안에서 수정합니다.
- **격리 실행기**: 생성 코드를 사용자 컴퓨터의 일반 프로그램과 분리해 실행합니다. 실제 저장소에는 Docker, 내장 예제에는 제한된 QuickJS 실행기를 사용합니다.
- **작업 저장소**: 단계와 산출물을 파일로 남기고 서버 재시작 후 이어갑니다.
- **Eve 에이전트**: 대화로 작업을 시작하고 진행 상태를 조회하거나 중단·재개합니다.
- **배포 연결기**: 검증된 정적 파일의 로컬 페이지 또는 Vercel Preview 주소를 만듭니다.

## 실행 기록과 재개

기록은 `.autoforge/runs/<실행 ID>/`에 저장됩니다. 요구사항, 설계, 테스트 원문, 코드 파일과 Git 변경 내역을 관리 화면의 결과물 탭에서 확인할 수 있습니다.

서버가 재시작되면 완료한 단계를 보존하고 진행 중 작업을 자동 재개합니다. 취소되었거나 연결정보가 필요한 작업은 재개 버튼으로 이어갑니다. 외부 배포 요청이 도착했는지 불확실한 경우에는 중복 배포를 만들지 않고 확인이 필요한 상태로 남깁니다. 작업은 한 번에 하나씩 실행합니다. 한 작업은 최대 20분, 자동 수정은 최대 8회로 제한됩니다.

테스트를 통과시키려고 기존 테스트나 최초 작성된 검증 파일·검사 명령을 바꾸는 변경은 거부합니다. 모델 검토도 함께 수행하지만 이 검토와 테스트가 모든 결함을 발견한다고 보장하지는 않습니다.

## 개발 및 검증 명령

```sh
npm test             # 실제 실패/수정·격리·API·재시작 검증
npm run typecheck    # 코드 형식 확인
npm run build        # 형식 확인 및 Eve 에이전트 빌드
```

관리 화면과 함께 대화형 에이전트를 쓰려면 별도 터미널에서 `npm run agent:chat`을 실행하세요. Eve의 모델 인증을 연결하면 `develop`, `inspect_job`, `manage_job` 도구로 관리 화면의 개발 작업을 제어할 수 있습니다. 로컬 미리보기는 제한된 브라우저 문맥을 사용하므로 브라우저 저장 기능(localStorage 등)은 제공하지 않습니다. Vercel Preview에서는 일반 웹사이트처럼 동작합니다. 기본 범용 도구는 꺼져 있으며 개발 엔진이 작업 공간과 실행 정책을 관리합니다. 에이전트의 별도 HTTP 실행은 `npm run agent:dev`입니다.

## 연결과 실행 정책

설정은 서버의 `.env`에 유지합니다. 모델이나 생성 컨테이너에 GitHub·Vercel 토큰을 넘기지 않습니다. 저장소 URL, 파일 경로, 크기·시간 한도를 코드에서 검사합니다. 의존성 설치 단계만 네트워크를 사용하며 설치 스크립트는 실행하지 않습니다. 테스트와 빌드는 네트워크가 차단된 Docker 컨테이너에서 실행합니다. 로컬 화면은 127.0.0.1에만 열고, 생성 페이지는 브라우저의 제한된 문맥에서 표시합니다. 여러 서버를 같은 데이터 폴더에 동시에 실행하지 마세요.
